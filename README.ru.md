# Смартфон как геймпад · Виртуальный контроллер Xbox 360 (Android → Windows)

**Язык / Language**: [简体中文](README.md) · [English](README.en.md) · [日本語](README.ja.md) · [Español](README.es.md) · [Русский](README.ru.md)

![License](https://img.shields.io/badge/license-MIT-green) ![Platform](https://img.shields.io/badge/platform-Windows%20%2B%20Android-blue) ![Transport](https://img.shields.io/badge/transport-UDP%20250Hz-orange) ![Version](https://img.shields.io/badge/release-v1.1.0-purple)

> **Одной строкой**: превращает Android-смартфон в контроллер Xbox 360, который Windows
> **распознаёт нативно**. Подключение напрямую по локальной сети: игра видит настоящий геймпад,
> а не эмуляцию клавиатуры и не макрос.

---

## Для кого это

| Ваша ситуация | Что вы получаете |
| --- | --- |
| Хочется играть в игры с геймпадом на ПК, а геймпада нет | Смартфон становится геймпадом; и `joy.cpl`, и игры показывают *Xbox 360 Controller for Windows* |
| Нужны 2–4 игрока на одном ПК, а геймпадов меньше | До **четырёх смартфонов на одном ПК** (1P–4P), у каждого свой геймпад, вибрация адресуется владельцу |
| В шутерах и открытых мирах не хватает скорости прицела | **Гироскопический прицел**: поворот смартфона поворачивает камеру, суммируется с правым стиком, без накопления дрейфа |
| Раскладка существующих приложений неудобна | 19 элементов с индивидуальными позицией / размером / прозрачностью, пять тем, светлая / тёмная / системная |
| Нужно подключить свои скрипты или устройства | UDP-протокол с пакетами по 20 байт и общими тестовыми векторами, лицензия MIT |

**Не подходит**: ритм-игры и файтинги с точными сериями (предел задаёт задержка Wi-Fi), старые игры
только с DirectInput, ПК на macOS / Linux.

## Чем отличается от других решений

| Подход | Игра видит настоящий геймпад | Что ставится на ПК | Аналоговые стики | Вибрация обратно |
| --- | --- | --- | --- | --- |
| Мапперы клавиатуры и мыши | ✗ только уровень клавиатуры | ничего | ✗ | ✗ |
| HID по Bluetooth со смартфона | зависит от игры; часто нужен Steam Input | ничего | ✓ | обычно ✗ |
| **Этот проект** | **✓ нативный XInput** | офлайн-драйвер 876 КБ, один раз | ✓ | ✓ |

Компромисс обозначен прямо: нужен **подписанный драйвер уровня ядра** (ViGEmBus). Это ограничение
Windows — из пользовательского режима нельзя заявить «геймпад подключён». У любого решения, которое
игры действительно принимают, на ПК есть драйвер. После установки все игры на XInput видят его
**нативно**.

## Ключевые возможности

| Возможность | Детали |
| --- | --- |
| Настоящее устройство, а не маппинг | Виртуальное устройство шины уровня ядра; перечисление XInput неотличимо от железа, стики 16 бит и триггеры 8 бит |
| Локальная игра 1P–4P | Слоты по IP источника, нумерация сохраняется при переподключении, вибрация уходит нужному смартфону |
| Гироскопический прицел | Объединённая ориентация (`Game Rotation Vector`, 50 Гц), суммируется с правым стиком, инверсия по осям отдельно |
| Две независимые чувствительности | «Камера гироскопом» и «камера правым стиком» — отдельные настройки 0–100, не влияют друг на друга |
| Вибрация обратно | `XInputSetState` игры → callback драйвера → вибрация смартфона, с настройкой силы / длительности / минимального интервала |
| Полный набор кнопок | ABXY, LB/RB, LT/RT (0–255 аналог), крестовина, `☰` Menu, `X` Home, L3/R3 — 19 элементов |
| Три режима нажатия стика | Тап по центру / двойной тап внутри стика / удержание при работе; наклон стика не даёт ложных срабатываний |
| Правка раскладки по элементам | Позиция / размер (50%–500%) / прозрачность / видимость, автосохранение; скрытый элемент не рисуется и не ловит касания |
| Интерфейс Material 3 + неоморфизм | Пять приглушённых тем с 480 мс переходом фона, светлая / тёмная / системная, анимация нажатия |
| Складная верхняя панель | Сворачивается в пилюлю «手柄»; при раскрытии геймпад размывается в реальном времени и появляется панель матового стекла |
| Самовосстановление связи | Обрывы Wi-Fi и перезапуск приёмника восстанавливаются с задержкой — измерено **~1 с** после перезагрузки ПК |
| Работает сразу | Портативный пакет содержит приёмник, APK и офлайн-драйвер; Python не нужен |

## Три шага до игры

**1 · Распакуйте портативный пакет**

```
VirtualGamepadReceiver-Portable/
├─ VirtualGamepadReceiver.exe     приёмник для ПК (без установки)
├─ 手机端/VirtualGamepad-v1.1.0-debug.apk    приложение для смартфона
├─ 可选驱动/ViGEmBusSetup_x64.msi            офлайн-драйвер 876 КБ
└─ 使用说明.txt
```

**2 · Установите драйвер один раз**

Правый клик по `可选驱动/ViGEmBusSetup_x64.msi` → запуск от имени администратора → **перезагрузка**.
Это драйвер ядра, он загружается только после перезагрузки. Повторять не нужно.

**3 · Подключите смартфон**

Установите APK из `手机端/`, подключитесь к той же Wi-Fi, что и ПК, нажмите пилюлю «手柄» слева
вверху, введите IPv4-адрес ПК и порт `26760`, подключитесь. Надпись `已连接 · 250 pps · 1P`
означает, что канал работает.

> Пошаговый список — в **[QUICKSTART.md](QUICKSTART.md)** (на китайском); сборка из исходников,
> эталонный приёмник на C# и ручной запуск — в **[docs/TECHNICAL.md](docs/TECHNICAL.md)**.
> При первом запросе брандмауэра Windows разрешите входящий UDP 26760 для **частных сетей**.

## Почему игра принимает это за настоящий геймпад

В Windows есть два независимых пути: **XInput** (`xinput1_4.dll`, почти все игры с поддержкой
геймпада с 2006 года) и более старый **DirectInput**. Программа в пользовательском режиме не может
подделать USB-устройство — поэтому обычные мапперы клавиш останавливаются на уровне клавиатуры.

**ViGEmBus** — подписанный драйвер шины KMDF: пользовательский режим через IOCTL просит подключить
контроллер Xbox 360 к виртуальной шине, Windows PnP перечисляет его и выделяет слот XInput.
Устройство появляется в Диспетчере устройств, `XInputGetState(0, …)` возвращает успех, а структура,
которую получает игра, идентична аппаратной.

**На уровне объектов ядра отличить его невозможно.** «Не распознаётся» — это почти всегда
отсутствующий драйвер, ПК без перезагрузки, незапущенный приёмник или игра только на DirectInput.

> ViGEmBus архивирован 2023-11-02 на версии 1.22.0. Это зрелый драйвер с одной задачей, он работает
> на Windows 10/11 включая 24H2; **версия 1.17.333 из этого пакета тоже полностью работоспособна**,
> гнаться за последней не нужно.

## Характеристики и границы

| Параметр | Измерено / спецификация |
| --- | --- |
| Транспорт | UDP unicast по Wi-Fi, пакеты по 20 байт, **250 Гц**, ~5 КБ/с |
| Задержка | обычно 10–20 мс в LAN; ~35–50 мс с учётом опроса касаний и одного кадра |
| Одновременно | до 4 смартфонов (предел слотов XInput) |
| Поддержка | всё на XInput — Steam, Epic, UE, Unity, RE Engine, RPCS3, Yuzu, RetroArch и др. |
| Не поддержано | старые игры только DirectInput, часть античитов против виртуальных устройств, ПК не на Windows |
| Проверка | 22/22 проверки уровня XInput, 13 кнопок попадают точно в свой бит, 250 pps без пропусков последовательности |

Безопасность и соответствие правилам: ставьте драйвер только из официального источника или из этого
пакета, избегайте сторонних «сборок всё в одном». Виртуальные устройства ввода допустимы в одиночных
и кооперативных играх, но **часть античитов в соревновательных проектах их ограничивает** — сверьтесь
с условиями игры. Весь трафик остаётся на вашем ПК и в локальной сети, сторонних серверов нет.
