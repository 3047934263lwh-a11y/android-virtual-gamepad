# Виртуальный геймпад Xbox 360 (Android → Windows)

**Язык / Language**: [简体中文](README.md) · [English](README.en.md) · [日本語](README.ja.md) · [Español](README.es.md) · [Русский](README.ru.md)

![License](https://img.shields.io/badge/license-MIT-green) ![Platform](https://img.shields.io/badge/platform-Windows%20%2B%20Android-blue) ![Protocol](https://img.shields.io/badge/transport-UDP%20125Hz-orange)

Используйте Android-смартфон как виртуальный геймпад Xbox 360. Стики, крестовина, ABXY, бамперы и триггеры передаются по локальной сети (UDP) на ПК, где драйвер уровня ядра **ViGEmBus** создаёт виртуальное XInput-устройство. Для игры это **настоящий контроллер Xbox 360** — без внедрения в процессы, без подмены DLL, без хуков API.

> Быстрый старт: [`QUICKSTART.md`](QUICKSTART.md) (на китайском). Те же шаги кратко ниже.

## Возможности

| Функция | Описание |
| --- | --- |
| Настоящий геймпад Xbox 360 | Виртуальное устройство на уровне ядра; XInput-игры видят его нативно |
| **Локальный мультиплеер (P1–P4)** | Несколько телефонов на одном ПК: каждому — свой геймпад и номер игрока; вибрация возвращается на «свой» телефон |
| **Прицеливание гироскопом** | Поворот телефона = поворот камеры (фьюжн-ориентация, без дрейфа); **складывается** с правым стиком; чувствительность гироскопа и правого стика независимы (0–100); переключатели инверсии |
| Обратная вибрация | Данные моторов из `XInputSetState` отправляются на телефон |
| Настройка каждого элемента | Положение / размер / прозрачность любого элемента с автосохранением |
| Тёмный «стеклянный» UI | Многослойное обсидиановое стекло, цветные буквы ABXY, анимация нажатия |
| Автопереподключение | Приложение само подключается к последнему серверу при запуске |
| **Складная верхняя панель** | Панель сворачивается до исходного текста «手柄»; касание раскрывает её вправо (300 мс), повторное — сворачивает. В свёрнутом виде занимает одно слово и не перехватывает касания игры |
| Запуск в один клик | Скрипт проверяет зависимости, чистит старые процессы, освобождает порт и запускает приёмник |
| Тестовые игры | 4 игры на ПК для проверки геймпада (платформер / twin-stick арена / камера / 3D-прогулка) |

## Почему игра «на 100% принимает» геймпад

Игры читают геймпады через **XInput** (`xinput1_4.dll`) или старый **DirectInput**. Программа уровня пользователя не может «воткнуть» USB-устройство — поэтому обычные мапперы умеют только эмулировать клавиатуру/мышь. **ViGEmBus** — подписанный драйвер шины (KMDF): пользовательская программа просит подключить контроллер Xbox 360 к виртуальной шине, диспетчер PnP Windows выполняет перечисление, и выделяется слот XInput. На уровне объектов ядра устройство не отличается от реального — технической возможности «распознать подделку» у игры нет. Если игра «не видит» геймпад — почти всегда: драйвер не установлен (или ПК не перезагружен), приёмник не запущен, либо игра работает только с DirectInput.

> ViGEmBus архивирован 02.11.2023, финальная версия **1.22.0**. Это зрелый стабильный драйвер, работает на Windows 10/11 включая 24H2.

## Быстрый старт

1. **Установите ViGEmBus** (один раз): <https://github.com/nefarius/ViGEmBus/releases>, запуск от администратора, затем **перезагрузите ПК**.
2. **Запустите приёмник**: двойной клик по `一键启动.bat` (или `START-RECEIVER.bat`, то же самое). Скрипт проверит Python и библиотеку `vgamepad` (установит при необходимости), драйвер, завершит старые процессы и начнёт слушать UDP 26760. Разрешите доступ в брандмауэре для частных сетей.
3. **Соберите Android-приложение** (только первый раз): откройте папку `android/` в Android Studio, дождитесь Gradle Sync, затем *Build APK(s)*. Установите `app/build/outputs/apk/debug/app-debug.apk` на телефон.
4. **Подключение**: телефон и ПК в одной Wi-Fi сети. Коснитесь текста **«手柄»** слева вверху, чтобы раскрыть панель, введите IPv4 компьютера и порт `26760`, нажмите «连接». Далее приложение **подключается автоматически**. Повторное касание текста сворачивает панель. В статусе появится `connected · 125 pps · P1`.
5. **Проверка**: `Win+R` → `joy.cpl` — должен появиться "Xbox 360 Controller for Windows". Проверьте стики и кнопки в свойствах.
6. **Запускайте игру после приёмника** (игры перечисляют геймпады при старте). Для Steam-игр отключите *Steam Input*.

**Мультиплеер**: каждый подключившийся телефон занимает следующий слот (P1–P4; у XInput максимум 4). Номер сохраняется при переподключении; консоль показывает статистику по игрокам: `[1P] 125pps 0.8%`.

## Кратко о протоколе

Пакеты ввода — **абсолютное состояние**, 20 байт, little-endian, 125 Гц (≈2,5 КБ/с):

| Смещение | Размер | Поле | Описание |
| --- | --- | --- | --- |
| 0 | 4 | magic | ASCII `VGP1` |
| 4 | 1 | version | `1` |
| 5 | 2 | buttons | битовая маска uint16: 0=A, 1=B, 2=X, 3=Y, 4=LB, 5=RB, 6=BACK, 7=START, 8=L3, 9=R3, 10–13=крестовина, 14=GUIDE (собственный порядок битов, НЕ совпадает с `XINPUT_GAMEPAD.wButtons`; приёмник преобразует побитово) |
| 7 | 1 | sequence | 0–255, статистика потерь |
| 8–15 | 8 | LX/LY/RX/RY | int16 ×4 (**LY: вверх — положительное**) |
| 16–17 | 2 | LT/RT | uint8 0–255 |
| 18 | 2 | reserved | 0 |

Обратный канал (8 байт, на фиксированный IPv4-порт **26761** телефона): `VGPR` — вибрация (моторы 0–255), `VGPP` — номер игрока (1–4).

Учтённые нюансы: ось Y экрана инвертирована относительно XInput, триггеры беззнаковые (отпущено = 0), крестовина — 4 кнопки, а не POV-hat. Тач-слой применяет радиальную мёртвую зону 6% с перенормировкой, чтобы полный наклон давал 32767. Приёмник опустошает очередь UDP и применяет только **последний** пакет каждого телефона — задержка постоянна, без «дрейфа» от устаревших пакетов.

## Настройки

| Что | Где |
| --- | --- |
| Гироскоп вкл/выкл, чувствительность, инверсия осей | Приложение → шестерёнка → секция правого стика (сразу применяется) |
| Положение / размер / прозрачность элементов | Приложение → шестерёнка → редактор раскладки: коснитесь элемента, перетащите; ползунок переключает размер/прозрачность |
| Порт приёмника | `python server.py 26761` (поменяйте и в приложении) |
| Скорости гироскопа | `GyroAim.kt`: `MAX_YAW_RATE / MAX_PITCH_RATE` |

Легенда консоли: `[监听]` ожидание · `[连接]` телефон подключён · `[1P] 125pps 0.8%` скорость/потери по игрокам · `[超时]` нет пакетов, ввод обнулён.

## Тестовые игры (`game/`)

Все читают XInput напрямую через ctypes (тот же путь API, что и у настоящих игр; pygame только рисует). У каждой есть `--selftest`.

| Игра | Что проверяет |
| --- | --- |
| `xbox_platformer.py` | Аналоговое движение + прыжок с накоплением, A/X/B/Y, ход триггеров, HUD ввода, 3 уровня |
| `twin_stick.py` | Движение левым стиком + прицел/огонь правым **одновременно**, волны, бомбы |
| `look_test.py` | Покадровая камера без сглаживания, компас, переносимый класс `LookCamera` |
| `fps_walk.py` | Два стика в стиле FPS (ходьба + обзор), спринт на RT, кольца-цели, миникарта |

## Устранение неполадок (основное)

| Симптом | Решение |
| --- | --- |
| «Не удается загрузить ViGEmBus» | Переустановите 1.22.0 и **перезагрузите ПК** |
| Нет контроллера в `joy.cpl` | Проверьте консоль приёмника; добавьте исключение в антивирус |
| Телефон «подключён», но на ПК логов нет | Брандмауэр / изоляция точек доступа: разрешите входящий UDP 26760 |
| В `joy.cpl` работает, в игре нет | Игра только с DirectInput или неверная настройка ввода |
| Ось гироскопа инвертирована | Переключатели инверсии в приложении |
| Двойные нажатия | Закройте DS4Windows / x360ce / vJoy |
| Задержки | Wi-Fi 5 ГГц или точка доступа телефона |

Полные таблицы: [китайский README](README.md) (§12) и `QUICKSTART.md`.

## Развитие

1. **USB-канал**: `adb forward tcp:26760 tcp:26760` + TCP с тем же протоколом.
2. **Обнаружение в LAN**: heartbeat от приёмника для автозаполнения IP.
3. **Поддержка DirectInput** (vJoy) для старых игр.
4. **Автономный EXE**: `pyinstaller --onefile --collect-all vgamepad server.py` — приёмник без установки Python.
