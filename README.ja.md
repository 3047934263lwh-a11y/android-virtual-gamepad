# 🎮 Android Virtual Gamepad

**言語 / Language**: [简体中文](README.md) · [English](README.en.md) · [日本語](README.ja.md) · [Español](README.es.md) · [Русский](README.ru.md)

## Android スマホを、本物の Xbox 360 ワイヤレスコントローラーに

実機パッドは不要。Wi-Fi で Android スマホを Windows PC につなぐだけで、ゲームは標準の Xbox 360 コントローラーとして認識します。

**主な機能**

- 🎮 **ネイティブなコントローラー再現**：Windows の XInput ゲームに対応。
- 👥 **ローカル多人数**：最大 4 台のスマホを同時接続。
- 🌀 **ジャイロエイム**：スマホの動きでゲーム内の視点を操作。
- 📳 **振動フィードバック**：ゲームの振動をスマホへ同期。
- 🎨 **自由なカスタマイズ**：ボタンの位置・サイズ・透明度・配置を調整。
- ⚡ **低遅延通信**：Wi-Fi UDP によるリアルタイム伝送。

**無料 · オープンソース · 実機パッド不要**

> «操作はスマホ、ゲームは PC。眠っているスマホをコントローラーに。»

## こんな人向け

| 状況 | 得られるもの |
| --- | --- |
| PC のパッド対応ゲームを遊びたいがパッドを持っていない | スマホがパッドに。`joy.cpl` でもゲーム内でも *Xbox 360 Controller for Windows* として表示 |
| ローカル 2〜4 人で遊びたいがパッドが足りない | 1 台の PC に最大 **4 台**（1P〜4P）、各自が独立したパッド、振動は本人の端末へ |
| シューターやオープンワールドでエイムが遅い | **ジャイロエイム**：端末を回すと視点が回る。右スティックに加算、累積ドリフトなし |
| 既存アプリのボタン配置が合わない | 19 個の操作部品を個別に位置・サイズ・透明度調整、テーマ 5 色、ライト／ダーク／システム追従 |
| 自作スクリプトや機器から繋ぎたい | 20 バイト固定長 UDP プロトコル、共有テストベクタ、MIT ライセンス |

## 他の「スマホをパッドにする」方法との違い

| 方法 | ゲームが本物のパッドと認識 | PC 側の導入 | アナログスティック | 振動の逆送 |
| --- | --- | --- | --- | --- |
| キーボード／マウスマッピング | ✗ キーボード相当のみ | 不要 | ✗ | ✗ |
| スマホの Bluetooth HID | ゲーム次第。多くは Steam Input 経由 | 不要 | ✓ | 通常 ✗ |
| **本プロジェクト** | **✓ XInput ネイティブ** | 初回のみ 876 KB のオフラインドライバ | ✓ | ✓ |

代償は明示的です：**署名済みカーネルドライバ**（ViGEmBus）が必要です。これは Windows の
境界で、ユーザーモードから「パッドが挿さった」と宣言することはできません。ゲームに本物と
認めさせる方式は、PC 側に必ずドライバがあります。一度入れてしまえば、XInput を使うゲームは
**ネイティブに**認識します。

## 3 ステップで開始

**1 · ポータブル版を展開**

```
VirtualGamepadReceiver-Portable/
├─ VirtualGamepadReceiver.exe     PC レシーバー（インストール不要）
├─ 手机端/VirtualGamepad-v1.1.3.apk    スマホアプリ
├─ 可选驱动/ViGEmBusSetup_x64.msi            876 KB オフラインドライバ
└─ 使用説明.txt
```

**2 · ドライバを一度だけ導入**

`可选驱动/ViGEmBusSetup_x64.msi` を右クリック → 管理者として実行 → **PC を再起動**。
カーネルドライバなので再起動後に読み込まれます。以後は何もしなくて構いません。

**3 · スマホを接続**

`手机端/` の APK を入れ、PC と同じ Wi-Fi に接続 → 左上の「手柄」をタップして接続バーを開く →
PC の IPv4 とポート `26760` を入力して接続。`已连接 · 250 pps · 1P` が出れば準備完了です。

> クリック単位の手順は **[QUICKSTART.md](QUICKSTART.md)**（中国語）、ソースからのビルド・
> C# リファレンス実装・手動起動は **[docs/TECHNICAL.md](docs/TECHNICAL.md)** を参照。
> 初回の Windows ファイアウォール確認では、**プライベートネットワーク**の UDP 26760 受信を許可してください。

## なぜ本物のパッドとして認識されるのか

Windows でゲームがパッドを読む経路は 2 つあります：**XInput**（`xinput1_4.dll`、2006 年以降の
ほぼすべてのパッド対応ゲーム）と、より古い **DirectInput**。ユーザーモードのプログラムは USB
デバイスを偽造できないため、単なる「キー割り当て」ツールはキーボード相当までしか到達しません。

**ViGEmBus** は署名済みの KMDF カーネルバスドライバです。ユーザーモードが IOCTL で
「仮想バスに Xbox 360 コントローラーを挿してほしい」と要求すると、Windows PnP が列挙して
XInput スロットを割り当てます。デバイスマネージャーにパッドが現れ、`XInputGetState(0, …)` が
成功し、ゲームが受け取る構造体は実機と同一になります。

**カーネルオブジェクトのレベルでは、ゲーム側に実機と区別する手段はありません。**
「認識しない」のほとんどは、ドライバ未導入／再起動忘れ／レシーバー未起動／DirectInput 専用タイトルです。

> ViGEmBus は 2023-11-02 にアーカイブされ、最終版は 1.22.0 です。単一責務の成熟したドライバで、
> Windows 10/11（24H2 含む）で安定動作します。**本パッケージ同梱の 1.17.333 も利用可能**で、
> 最新版を追う必要はありません。

## 仕様と限界

| 項目 | 実測／仕様 |
| --- | --- |
| 伝送 | Wi-Fi UDP ユニキャスト、20 バイト固定、**250 Hz**、約 5 KB/s |
| 遅延 | LAN で通常 10〜20 ms。タッチサンプリングと 1 フレームを含めると約 35〜50 ms |
| 同時接続 | 最大 4 台（XInput スロット上限） |
| 対応範囲 | XInput を使うゲーム／エミュレータ全般（Steam、Epic、UE、Unity、RE Engine、RPCS3、Yuzu、RetroArch など） |
| 非対応 | DirectInput 専用の旧作、仮想デバイスを制限する対戦ゲームの一部、Windows 以外のホスト |
| 検証 | XInput 層 22/22 項目合格、プロトコル層 13 ボタンが単一ビットで正確に一致、250 pps・シーケンス欠落 0 |

安全とコンプライアンス：ドライバは公式または本パッケージから導入し、第三者の「統合版」は避けて
ください。仮想入力デバイスはシングル／協力プレイでは問題ありませんが、**対戦ゲームの
アンチチートが制限する場合があります**。利用前に各ゲームの規約を確認してください。
通信は端末と LAN 内のみで、外部サーバーを経由しません。
