# 仮想 Xbox 360 コントローラー（Android → Windows）

**言語 / Language**: [简体中文](README.md) · [English](README.en.md) · [日本語](README.ja.md) · [Español](README.es.md) · [Русский](README.ru.md)

![License](https://img.shields.io/badge/license-MIT-green) ![Platform](https://img.shields.io/badge/platform-Windows%20%2B%20Android-blue) ![Protocol](https://img.shields.io/badge/transport-UDP%20125Hz-orange)

Android スマホを仮想 Xbox 360 コントローラーとして使います。スティック・十字キー・ABXY・ショルダー・トリガーの入力を LAN の UDP 経由で PC へ送信し、PC 側では **ViGEmBus** カーネルドライバーが仮想 XInput デバイスを生成します。ゲームから見ると**本物の Xbox 360 コントローラー**です——プロセス注入も DLL 差し替えも API フックも行いません。

> 手早く使い始めたい方は [`QUICKSTART.md`](QUICKSTART.md)（中国語）をどうぞ。以下に同じ手順を日本語でまとめます。

## 主な機能

| 機能 | 説明 |
| --- | --- |
| 本物の Xbox 360 パッド | カーネルレベルの仮想デバイス。XInput ゲームがネイティブ認識 |
| **ローカルマルチプレイ（1P–4P）** | 複数のスマホを 1 台の PC に接続。各自に独立したパッドとプレイヤー番号を割り当て、振動は対応するスマホへ返送 |
| **ジャイロエイミング** | スマホを回す = 視点を回す（融合姿勢推定でドリフトなし）。右スティックに**加算**。感度 40–300%、ピッチ/ヨーの反転スイッチあり |
| 振動フィードバック | `XInputSetState` のモーター値をスマホへ返送 |
| コントロール単位のカスタマイズ | 位置 / サイズ / 透明度をコントロールごとに調整・自動保存 |
| ダークガラス UI | 黒曜石風の多層ガラス。ABXY は高コントラストのカラー文字。押下時の沈み込み演出付き |
| 自動再接続 | アプリ起動時に前回のサーバーへ自動接続 |
| **フローティング接続ドロワー** | 上部の接続バーは既定で収納され、左端の小さな「手柄」タブ（接続中は緑ドット）だけが表示されます。タップで 300ms のイージングでスライド表示、再タップまたは外側タップで収納。収納時はゲームのタッチを一切遮りません |
| ワンクリック起動 | PC 側スクリプトが依存関係チェック・残存プロセス掃除・ポート確認をして受信側を起動 |
| テスト用ゲーム同梱 | パッド検証用の PC ゲーム 4 本（横スクロール / ツインスティック / カメラテスト / 3D ウォーク） |

## なぜ「100% 認識される」のか

ゲームは **XInput**（`xinput1_4.dll`）か旧 **DirectInput** でパッドを読みます。ユーザーモードのプログラムは USB 機器の挿入を偽装できないため、普通の「キーマップツール」はキーボード/マウスの模倣しかできません。**ViGEmBus** は署名済みの KMDF カーネルバスドライバーで、仮想バスに Xbox 360 コントローラーを挿入するよう依頼すると Windows の PnP マネージャーが列挙し、XInput スロットが割り当てられます。カーネルオブジェクトのレイヤーでは実機と区別がつかないため、ゲームが仮想と判別する技術的経路は存在しません。「認識されない」ケースのほとんどは、ドライバー未インストール（またはインストール後の再起動忘れ）・受信側未起動・DirectInput 専用の古いゲームのいずれかです。

> ViGEmBus は 2023-11-02 にアーカイブされ、最終版は **1.22.0**。成熟した安定ドライバーで、Windows 10/11（24H2 含む）で正常に動作します。

## クイックスタート

1. **ViGEmBus をインストール**（初回のみ）: 公式リリース <https://github.com/nefarius/ViGEmBus/releases> からダウンロードし、管理者として実行、その後**再起動**。
2. **受信側を起動**: `一键启动.bat`（または同じ内容の `START-RECEIVER.bat`）をダブルクリック。Python と `vgamepad` ライブラリの確認（無ければ自動インストール）、ドライバー確認、残存プロセスの掃除を行い、UDP 26760 で待ち受けます。ファイアウォールの画面ではプライベートネットワークを許可。
3. **Android アプリをビルド**（初回のみ）: Android Studio で `android/` フォルダーを開き、Gradle 同期後に *Build APK(s)*。生成された `app-debug.apk` をスマホへインストール。
4. **接続**: スマホと PC を同じ Wi-Fi に。左端の**「手柄」タブ**をタップして接続ドロワーを開き、PC の IPv4 アドレスとポート `26760` を入力して接続。以後は起動時に**自動接続**されます。タブをもう一度タップするか外側をタップすると収納されます（タブの緑ドットが接続中を示します）。ステータスバーに `已连接 · 125 pps · 1P` と出れば成功（数字はプレイヤー番号）。
5. **確認**: `Win+R` → `joy.cpl` で "Xbox 360 Controller for Windows" が表示されることを確認し、プロパティのテストパネルで入力を確認。
6. **ゲームを起動**: 受信側を起動してからゲームを起動（ゲームは起動時にパッドを列挙するため）。Steam のゲームは *Steam Input* を無効化推奨。

**マルチプレイ**: 接続順に 1P–4P のスロットを自動割り当て（XInput は最大 4 台）。再接続でも番号は維持され、受信側コンソールには `[1P] 125pps 0.8%` のように各プレイヤーの状況が出ます。

## プロトコル概要

入力パケットは**絶対状態**・20 バイト固定長・リトルエンディアン・125 Hz（約 2.5 KB/s）:

| オフセット | サイズ | フィールド | 内容 |
| --- | --- | --- | --- |
| 0 | 4 | magic | ASCII `VGP1` |
| 4 | 1 | version | `1` |
| 5 | 2 | buttons | ビット 0=A, 1=B, 2=X, 3=Y, 4=LB, 5=RB, 6=BACK, 7=START, 8=L3, 9=R3, 10–13=十字キー, 14=GUIDE（`XINPUT_GAMEPAD.wButtons` と同一レイアウト） |
| 7 | 1 | sequence | 0–255、ロス統計用 |
| 8–15 | 8 | LX/LY/RX/RY | int16 ×4（**LY は上方向が正**） |
| 16–17 | 2 | LT/RT | uint8 0–255 |
| 18 | 2 | reserved | 0 |

逆方向チャネル（8 バイト、スマホの固定 IPv4 ポート **26761** へ）: `VGPR` は振動（大/小モーター 0–255）、`VGPP` はプレイヤー番号（1–4）。

実装済みの注意点：画面 Y 軸と XInput の Y 軸の向きの違い（LY の反転）、トリガーは符号なし（解放 = 0）、十字キーは POV ハットではなく 4 ボタン。タッチ層は 6% の放射状デッドゾーンを再正規化し、最大倒れ込みでも 32767 に達します。受信側は UDP キューを排空して**最新の 1 パケットのみ**適用するため、遅延が一定で古いパケットによる「ドリフト」が起きません。

## 調整項目

| 内容 | 場所 |
| --- | --- |
| ジャイロ ON/OFF・感度・ピッチ/ヨー反転 | アプリ → 歯車 → 右スティック設定（即時反映） |
| コントロールの位置 / サイズ / 透明度 | アプリ → 歯車 → レイアウト編集：コントロールをタップしてドラッグ、スライダーはサイズ⇄透明度を切り替え |
| 受信ポート | `python server.py 26761`（アプリ側も変更） |
| ジャイロ感度のレート | `GyroAim.kt` の `MAX_YAW_RATE / MAX_PITCH_RATE` |

受信側コンソールの表記：`[监听]` 待機中 · `[连接]` スマホ接続 · `[1P] 125pps 0.8%` プレイヤー別のレート/ロス · `[超时]` 送信停止で入力を中立化。

## テスト用ゲーム（`game/`）

すべて ctypes で XInput を直接読みます（実ゲームと同じ API 経路。pygame は描画のみ）。`--selftest` でヘッドレス自己テスト対応。

| ゲーム | 検証内容 |
| --- | --- |
| `xbox_platformer.py` | アナログ移動 + 蓄積ジャンプ、A/X/B/Y、トリガー深度、入力 HUD、3 ステージ |
| `twin_stick.py` | 左スティック移動 + 右スティック エイミング/発射の**同時操作**、ウェーブ、ボム |
| `look_test.py` | フレーム直映カメラ（スムージングなし）、コンパス、移植可能な `LookCamera` クラス |
| `fps_walk.py` | FPS 型の移動 + 視点、RT ダッシュ、目標リング、ミニマップ |

## トラブルシューティング（主なもの）

| 症状 | 対処 |
| --- | --- |
| 起動時に「ViGEmBus を読み込めない」 | 1.22.0 を入れ直して**再起動** |
| `joy.cpl` に表示されない | 受信側のコンソールを確認。セキュリティソフトの除外へ |
| スマホは接続済みだが PC にログがない | ファイアウォール / AP 隔離。UDP 26760 の受信を許可 |
| `joy.cpl` では動くがゲームで動かない | DirectInput 専用ゲーム、またはゲーム内入力設定 |
| ジャイアの向きが逆 | アプリの「ピッチ反転」「ヨー反転」スイッチ |
| 二重入力 | DS4Windows / x360ce / vJoy を終了 |
| 遅延が大きい | 5 GHz Wi-Fi またはスマホのテザリングへ |

詳細な表は[中国語版 README](README.md)（§12）と `QUICKSTART.md` を参照してください。

## 拡張の方向性

1. **USB 伝送**: `adb forward tcp:26760 tcp:26760` + 同プロトコルの TCP 化。
2. **LAN 自動発見**: 受信側がハートビートをブロードキャストし、アプリが IP を自動入力。
3. **DirectInput 対応**（vJoy バックエンド）。
4. **単体 EXE 化**: `pyinstaller --onefile --collect-all vgamepad server.py` で Python 不要の受信側が作れます。
